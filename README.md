# Search-Retrieval

Поиск объявлений Avito Услуги по короткому запросу с учётом гео и фильтров:
2 452 запроса бенчмарка против корпуса из 189 212 объявлений, метрика — recall@50.

## Структура

| Папка | Что там |
|---|---|
| `notebooks/` | EDA (`01`), разбор `infm_params` (`02`), просмотр обработанного train (`03`) |
| `src/` | библиотечный код: предобработка, разбиение, тексты, отсечение, BM25, dense, оценка |
| `run/` | скрипты для запуска |
| `dataset/` | данные и производные (не в git) |
| `results/` | таблицы метрик |

## Как получить текущие результаты

Нужны сырые файлы в `dataset/`: `train.parquet`, `benchmark_queries.parquet`,
`benchmark_items.parquet`. Скрипты запускаются из корня репозитория по порядку:
каждый читает результат предыдущего.

```bash
python run/preprocess.py
python run/make_split.py
python run/encode_catalog.py
python run/evaluate_retrievers.py
```

Шаги 3 и 4 используют dense-модели, для них нужно окружение с `torch` и
`sentence-transformers` и GPU (conda `torch_env`). Остальные шаги работают в
любом окружении с `pandas`, `pyarrow`, `scikit-learn` и `snowballstemmer`.

### 1. `run/preprocess.py` — предобработка

`dataset/*.parquet` → `dataset/processed/*.parquet`.

* удаляет вырожденные колонки запроса `search_category` и `search_is_delivery_search`;
* переводит цену и координаты из `decimal128` в `float64`;
* разбирает `infm_params_text` (`src/infm_params.py`): фильтры запроса `filter_*`
  (вид и тип услуги, предмет, онлайн-запись) и те же поля у объявления `item_*`;
* заменяет `item_category_id` флагом `item_is_service`.

`--dry-run` показывает план изменений, ничего не записывая.

### 2. `run/make_split.py` — разбиение и каталог

`dataset/processed/train.parquet` → `dataset/split/` · несколько секунд.

* схлопывает повторы пар «поисковое событие → объявление» (событие — текст
  запроса, город и фильтры);
* делит **по тексту запроса**: 10% текстов целиком уходят в валидацию («новый
  текст»), и к ним добавляются события знакомых текстов, чтобы их доля была 37%,
  как в бенчмарке («знакомый текст»);
* собирает каталог для поиска: равномерная выборка 189 212 объявлений — размер
  корпуса бенчмарка;
* оставляет в валидации события, у которых от 1 до 50 позитивов в каталоге.

Результат: `train_pairs`, `val_pairs`, `val_eval` (32 891 событие к оценке),
`catalog`, `config.json`. Параметры задаются флагами (`--seed`,
`--catalog-mode` и др., см. `--help`); при значениях по умолчанию разбиение
воспроизводится один в один.

### 3. `run/encode_catalog.py` — эмбеддинги каталога

`dataset/split/catalog.parquet` → `dataset/embeddings/<модель>/` · около часа на модель.

Кодирует документы каталога (заголовок + очищенное описание, первые 512
токенов) моделями `intfloat/multilingual-e5-large` и `ai-forever/ru-en-RoSBERTa`.
Эмбеддинги сохраняются частями: прерванный запуск продолжается с последней
готовой части. Шаг необязательный — оценка досчитает недостающее сама, — но его
удобно запустить отдельно. Одна модель: `--models e5-large`.

### 4. `run/evaluate_retrievers.py` — оценка ретриверов

`dataset/split/` + кэш эмбеддингов → `results/retrievers/` · около 6 минут.

Для каждого события валидации ищет топ-50 в каталоге ретриверами BM25,
e5-large, RoSBERTa и их слиянием RRF — при четырёх вариантах отсечения
кандидатов: без отсечения, только фильтры запроса, только город запроса, оба
вместе. Для ориентира считает потолок (доля позитивов, переживших отсечение) и
recall при случайном порядке внутри пула.

Печатает и сохраняет:

| Файл | Что в нём |
|---|---|
| `recall.csv` | recall@50: ретриверы × варианты отсечения |
| `hit_rate.csv` | доля событий с хотя бы одним позитивом в топ-50 |
| `by_slice.csv` | recall по срезам «новый / знакомый текст» |
| `complementarity_*.csv` | доля событий, которые находит один ретривер и не находит другой |
| `per_event.parquet` | recall каждого события — для разбора ошибок |
| `config.json` | параметры запуска и разбиения |

Только часть ретриверов: `--retrievers BM25 e5-large`; без RRF: `--no-rrf`.

## Текущие результаты

recall@50 на валидации, dense-модели без дообучения:

| | без отсечения | только фильтры | только гео | фильтры + гео | гео + добивка |
|---|---|---|---|---|---|
| потолок | 100% | 96.94% | 80.98% | 78.65% | 99.26% |
| случайный порядок | 0.03% | 1.42% | 13.75% | 43.52% | — |
| BM25 | 24.74% | 26.14% | 74.94% | 75.57% | 79.76% |
| e5-large | 25.55% | 26.83% | 76.38% | 76.02% | 81.26% |
| RoSBERTa | 22.28% | 23.83% | 74.57% | 74.95% | 78.91% |
| **RRF (все три)** | 27.83% | 28.90% | 78.05% | 76.95% | **83.46%** |

«Гео + добивка» — топ внутри города запроса, добитый до 50 лучшими из «только
фильтры»; так собирается ответ на бенчмарке (`run/retrieve_benchmark.py`).

Главное: качество определяет город (тот же BM25 без гео даёт 25%, в пуле города —
75%), а внутри города ранжирование уже близко к потолку. Жёсткое отсечение по
городу теряет 19% позитивов ещё до ранжирования; добивка свободных мест
кандидатами из других городов возвращает часть из них (+5.4 п.п. у RRF).
Подробнее — в докстринге `src/evaluate.py`.

## Ответ на бенчмарк

```bash
python run/retrieve_benchmark.py   # -> results/benchmark/answer.csv
```

RRF трёх ретриверов, «гео + добивка». Первый запуск кодирует корпус
benchmark_items обеими dense-моделями (около 2 часов, кэш в
`dataset/embeddings/benchmark/`). `answer.csv` проверяется на требования задания
перед сохранением. Быстрый вариант без dense-моделей: `--retrievers BM25`.

### Попытки

| # | Конфигурация | Валидация | Ожидание* | Бенчмарк |
|---|---|---|---|---|
| 1 | BM25, «гео + добивка» (`--retrievers BM25`) | 79.76% | 77.2% | **75.18%** |

\* Валидация, перевзвешенная под долю запросов без города в корпусе (17.4% на
бенчмарке против 12.2% на валидации): у таких запросов «город» — это регион,
который не встречается среди городов объявлений, и гео для них не работает.
