# План: переранжировщик (второй этап)

Сейчас: RRF (BM25 + e5-large + RoSBERTa), «гео + добивка», гео регионов —
recall@50 на валидации **87.83%**, на бенчмарке **85.18%**. Потолок кандидатов
при 300 штуках («гео + квота 20% вне гео») — **95.1%**: столько позитивов уже
находится, но часть стоит на местах 51–300.

## Схема

1. **Кандидаты** — текущий пайплайн, 300 на событие: 80% мест — топ RRF внутри
   гео, 20% — лучшие из «только фильтры» (вне гео).
2. **Переранжировщик** — вектор признаков пары «событие — кандидат» → скор → топ-50.

## Данные

| Часть | Откуда | Зачем |
|---|---|---|
| обучение | события `train_pairs` с позитивом в каталоге (~150 тыс.) | обучение |
| val-tune | половина `val_eval` (по тексту запроса) | ранняя остановка, гиперпараметры |
| val-test | вторая половина `val_eval` | итоговое сравнение с RRF |

Для обучения на событие — все позитивы, ~50 самых высоких по RRF негативов и
~50 случайных из остальных; для валидации и бенчмарка — все 300.

**Без утечек:** таблица «регион → локации» и статистики по train для обучающих
событий считаются по фолдам (по тексту запроса): для фолда i — по остальным.

## Признаки пары

| Группа | Признаки |
|---|---|
| текст | скоры и ранги BM25, e5, RoSBERTa, RRF; кандидат из гео или из квоты |
| гео | тот же город; запрос с регионом; доля позитивов региона в локации объявления; расстояние, км; размер локации |
| фильтры | совпадение вида, типа, предмета, онлайн-записи; есть ли фильтры |
| объявление | рейтинг (+ пропуск), log отзывов, log цены (+ «не указана»), микрокатегория, флаги, длина описания |
| статистики train | популярность объявления; было ли позитивом для того же текста; «текст ↔ микрокатегория»; частота текста |
| запрос | число слов, есть ли текст в train |

## Модели

1. LightGBM LambdaRank (группа — событие) — база.
2. MLP + lookup-эмбеддинги (микрокатегория, локация, вид/тип услуги), softmax по кандидатам события.
3. Ансамбль, если обе дают прирост.

## Оценка и бенчмарк

* val-test: recall@50, разбивка город/регион и новый/знакомый текст, против RRF на тех же событиях.
* Бенчмарк: кандидаты по корпусу бенчмарка, статистики по всему train, финальная
  модель на `train_pairs` + `val_pairs`; отправка при приросте ≥ 0.5 п.п. на val-test.

## Риски

* Ложные негативы: 36.6% заголовков дублируются.
* Обучающие события ищут по каталогу валидации, бенчмарк — по своему корпусу (размер тот же).
